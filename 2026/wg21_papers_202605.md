### [P3377R0 constexpr `reinterpret_cast` partial replacements](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2026/p3377r0.html)

定数式で使用可能な`reinterpret_cast`の代替機能の提案。

`reinterpret_cast`は定数式での使用が一切認められておらず、それによって`std::function`や`std::any`などの型消去を伴うようなライブラリ型を`constexpr`対応させることが妨げられています。

`reinterpret_cast`が定数式で使用できないのは、容易に未定義動作を踏む可能性があり（間違って使用しても意図しないフォールバックによって動作してしまう）、かつその汎用性が高すぎる（担っている機能が多数集積している）ことで、定数式においてポインタの安全な利用を保証することが困難になるためです。

この提案では、現在`reinterpret_cast`が担っている役割をユースケースごとに分離し、ユースケースごとに個別の定数式で使用可能な専用キャスト機能を追加することで定数式でも安全に`reinterpret_cast`の必要な機能を使用できるようにしようとしています。

この提案によるユースケース分類と、対応する機能を提案するかどうかは次のようになります

| 機能 | 提案 |
|---|---|
|ポインタ型と整数型の相互変換| しない |
|ポインタのタギング| P3125（C++26） |
|包含する型のポインタへのキャスト| する |
|オブジェクトのバイト列へのアクセス| しない |
|浮動小数点数ビット列の読み替え| `std::bit_cast` |
|整数ポインタの変換| しない |
|バイト配列をストレージとして利用する| する |
|バイト配列内オブジェクトのコピー| する |
|関数とオブジェクトのポインタ変換| しない |
|関数ポインタの型消去| する |
|メンバ変数ポインタの型消去| する |
|メンバ関数ポインタの型消去| する |

#### ポインタ型と整数型の相互変換

これは、ポインタ値を整数型に変換し、またその逆変換を行うことです。

```cpp
intptr_t iptr = reinterpret_cast<intptr_t>(ptr);  // 整数値への変換
auto * optr = reinterpret_cast<pointer>(iptr);    // ポインタ値へ戻す
```

これは

- ポインタのタギング
- 整数を引数に取る低レベルインターフェースへのポインタ受け渡し
- オブジェクトのサイズやアラインメントを意図的に無視するポインタ演算

などの用途があります。

ARM64eのポインタ認証や、C++定数評価機のようにアドレスが整数値のセマンティクスを持たないような場合に正しく動作させることが困難です。

この提案ではこれを可能にすることは提案していません。

#### ポインタのタギング

これは、ポインタの未使用ビットをタグとして利用することです。基本的に整数値に戻してビット演算などによってタグを埋め込むため、前項のアドレスと整数値の変換のユースケースの一部です。

これはC++26においてP3125の`std::tagged_pointer`によって定数式でも可能になっています。

```cpp
auto tptr = std::tagged_pointer<int, bool, 1>(&value); // tag is bool and we need only one bit

bool has_tag = tptr.tag(); // it's already bool
int * iptr = tptr.pointer(); // it's already correct pointer

assert(iptr == &value);
```

#### 包含する型のポインタへのキャスト

これは、標準レイアウト型においてメンバポインタからそのメンバが属するクラスのポインタへ変換することです。

```cpp
struct outer_t { int first; int second; };

outer_t outer{1,2};
auto * out1 = reinterpret_cast<outer_t *>(&outer.first);
auto * out2 = reinterpret_cast<outer_t *>(&outer.second); // ub
```

標準レイアウト型であれば共通初期シーケンス（common initial sequence）に一致する部分のポインタ変換を安全に行うことができます。`out2`の場合は共通初期シーケンスのポインタではないのでUBとなります。

この提案では`std::enclosing_cast`としてこのユースケース用のキャスト関数を提案しています。

```cpp
struct outer_t { int first; int second; };

outer_t outer{1,2};
auto & out1 = std::enclosing_cast<&outer_t::first_member>(outer.first);   // ok
auto & out2 = std::enclosing_cast<&outer_t::second_member>(outer.second);	// ok
```

#### オブジェクトのバイト列へのアクセス

これは、オブジェクトの領域を`std::byte`配列としてアクセスするためにポインタを`std::byte*`へキャストすることです。

```cpp
auto * bytes = reinterpret_cast<std::byte *>(obj);
```

ポインタを`std::byte*`に変換して読み出すことは（配列外参照が無い限り）合法であり、このキャストは問題ありません。

このユースケースのためのものは提案していません。

#### 浮動小数点数ビット列の読み替え

これは、浮動小数点数型のポインタを整数型ポインタにキャストしてアクセスすることで浮動小数点数のビット表現を取得しようとするものです。

```cpp
double pi = 3.14;
auto bits_of_pi = reinterpret_cast<int64_t>(pi);  // このキャストはUB
memcpy(bits_of_pi, pi, sizeof(pi)); // this is not UB
```

これはもろにstrict aliasing rulesに触れるためキャストからUBです。

このようなユースケースはC++20の`std::bit_cast`を使用することで安全に（定数式でも）利用可能です。

```cpp
double pi = 3.14;
auto bits_of_pi = std::bit_cast<uint64_t>(pi);
```

#### 整数ポインタの変換

これは整数型のポインタを符号の異なる整数型のポインタへキャストすることです。

```cpp
int * iptr = ...;
auto * uptr = reinterpret_cast<unsigned *>(iptr);
```

このユースケースのためのものは提案していません。

#### バイト配列をストレージとして利用する

これは、バイト配列（`char`の配列）を別の型のオブジェクトのストレージとして利用しようとするときのキャストです。

```cpp
char storage[N];
new(&storage[0]) T (...);
T * ptr = reinterpret_cast<T *>(&storage[0]); // 有効なポインタではない
```

このようなことを安全に行うには配置`new`の戻り値のポインタを保持しておく必要があります。

```cpp
std::array<char, N> storage;
new(storage.data()) T(...);   // ok
T & ref = std::object_cast<T>(storage.data());  // ok
```

この提案では、`std::object_cast`としてこのようなキャストをサポートしようとしています。

#### バイト配列内オブジェクトのコピー

これは、コピーしてきたバイト配列をオブジェクト表現として利用して新しいオブジェクトの生存期間を開始することです。

```cpp
memcpy(other_storage, storage, N);
T * first = std::start_lifetime_as<T>(&other_storage[0]); // 定数式で使用できない
T * rest = reinterpret_cast<T*>(&other_storage[0]); // UB
```
```cpp
std::array other_storage = storage; // trivially copyable T
T & all = std::object_cast<T>(other_storage.data());
```

提案では、`std::object_cast`でこのようなユースケースをサポートしようとしています。

#### 関数とオブジェクトのポインタ変換

これは、関数ポインタをオブジェクトポインタにキャストして、それを元に戻すことです。

```cpp
auto * optr = reinterpret_cast<T *>(fptr); // yes, really
auto * fptr = reinterpret_cast<int(*)()>(optr);
```

このようなキャストはポインタのサイズが合う限りは条件付きでサポートされているようで、`void*`を受け取るインターフェースにコールバックを渡す際などに使用されることがあるようです。

標準ライブラリの機能を定数式対応させるためには不要なので、このユースケースのためのものは提案していません。

#### 関数ポインタの型消去

これは、関数ポインタを`void(*)()`のようなポインタに型消去してから元に戻すキャストの事です。

```cpp
auto * erased = reinterpret_cast<void(*)()>(fptr);
int(*fptr)() = reinterpret_cast<int(*)()>(erased);
```

型消去したポインタを用いて関数呼び出しを行わない限りはUBにならないようです。関数ポインタを受け取るインターフェースに対して型が合わな関数を渡すために使用されることがあるようです。

```cpp
auto erased = std::a_function_pointer{fptr};

auto fptr = function_pointer_cast<int()>(erased);
auto fptr = static_cast<int(*)>(erased); // alt
```

この提案では、`a_function_pointer`と`function_pointer_cast`でこのようなユースケースをサポートしようとしています。

#### メンバ変数ポインタの型消去

これは、メンバ変数ポインタを空のクラスのメンバポインタにキャストして元に戻すことです。

```cpp
struct empty_t {}; // yes you can do a member pointer of this
auto * erased = reinterpret_cast<int (empty_t::*)>(mdptr);
auto mdptr = reinterpret_cast<float (my_type::*)>(erased);
```
```cpp
auto erased = std::a_member_data_pointer{mdptr};

auto mdptr = member_pointer_cast<float (my_type::*)>(erased);
auto mdptr = static_cast<float (my_type::*)>(erased); // alt
```

この提案では、`a_member_data_pointer`と`member_pointer_cast`でこのようなユースケースをサポートしようとしています。

#### メンバ関数ポインタの型消去

これは、一つ前のユースケースのメンバ関数ポインタ版です。

```cpp
struct empty_t {}; // yes you can do a member pointer of this
auto * erased = reinterpret_cast<void (empty_t::*)()>(mfptr);
auto mfptr = reinterpret_cast<int (my_type::*)(float)>(erased);
```
```cpp
auto erased = std::a_member_function_pointer{mptr};

auto mfptr = member_pointer_cast<int (my_type::*)(float)>(erased);
auto mfptr = static_cast<int (my_type::*)(float)>(erased); // alt
```

この提案では、`a_member_function_pointer`と`member_pointer_cast`でこのようなユースケースをサポートしようとしています。

メンバ変数ポインタとメンバ関数ポインタを区別して扱っているのは、メンバ変数ポインタとメンバ変数ポインタでそのサイズが異なる場合があるためです。


`a_function_pointer`、`a_member_data_pointer`、`a_member_function_pointer`は上記例ではキャスト関数のように使用されていますが、ポインタの値を保持するために領域が必要になるため、その実態はクラス型です。提案ではライブラリ型としてこれらの機能を提案していますが、言語機能としてこれらの型を提供することで汎用的なコードでの取り扱いが簡単になる可能性があります。

この提案の主目的は定数式で`reinterpret_cast`相当の機能を使用可能にすることにありますが、ここで提案されている機能は定数式専用ではなく実行時にも使用可能にすることを意図しています。これによって、現在`reinterpret_cast`を使用していることで何がしたいのかが不明瞭になっているコードでも、よりユースケースに特化したこの提案による機能を使用することでコードの意図が明確になります。

### [P4036R0 Info: Why Span Is Not Enough](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2026/p4036r0.pdf)

I/Oの観点から、バイト列を表現するベストな型を考察する文書。

バイトシーケンスを表す型としては`std::span<std::byte>`が一番に上がりますが、この文書ではI/O処理においてはそれだと使いづらい面があり、専用のバッファ型が必要になる事を説明しています。

`span<byte>`では不十分な理由は、プラットフォームで定義されるI/O操作が多くの場合1つのバイトバッファ（領域）を取るのではなくバイト領域の配列を取るようになっているためです。これにより、`span<byte>`はI/Oのためのバッファを表現するのに不十分となります。

`span<span<byte>>`ならばバッファ配列を表現することができます。しかし、バッファそのもの（`span<byte>`）はどこかに実体を持ちそれを借用するだけだったとしても、そのビューの配列（`span<span<byte>>`）が必ずしもそうであるとは限りません。バッファ配列そのものの所有権はどこか別の場所にあるものではなく、そうしないと関数の呼び出し境界で`span<span<byte>>`を返す事で容易にダングリングしてしまいます。

```cpp
class message {
  span<span<byte>> buffers_; // borrows... what?
};

span<span<byte>> prepare_message(span<byte> hdr, span<byte> body) {
  span<byte> bufs[] = { hdr, body };
  return { bufs }; // dangling
}

void start_send(socket& s, span<byte> hdr, span<byte> body) {
  span<byte> bufs[] = { hdr, body };
  s.async_send(span<span<byte>>(bufs), callback);
  // returns immediately; bufs destroyed; dangling
}
```

`vector<span<byte>>`のように`span<byte>`の`range`にすればこの問題を解消することができます。この場合は、バッファ配列全体を1つのバッファとして扱ってバッファの消費を表現することができません。`vector<span<byte>>`に対してRangeアダプタを適用しても、バッファ単位の操作になりバイト要素単位ではありません。バッファ配列という構造を維持したままバッファの消費という操作を行う方法が無いため、この表現は適していません（`views::join`はバッファ配列という構造が維持されないので選択肢に上がらない）。

そのような操作が追加されたとしても、`std::span<byte>`がすでにバイト配列のビューとして使用されすぎているために、I/O専用のバッファ操作アルゴリズム（Rangeアダプタ）は`std::span<byte>`によって表現されているものがI/Oバッファなのかそれ以外のもの（シリアライズ・暗号化・ハッシュ・メモリマップなど）を区別できません。これにより、I/Oバッファ専用のデバッグなどを組み込むことが難しくなり、安全性が損なわれます（`BOOST_ASIO_ENABLE_BUFFER_DEBUGGING`のようなもの）。

この文書では、Boost.Asioの`mutable_buffer`（書き込み可能バッファ）/`const_buffer`（読み込み専用バッファ）がI/Oのためのバッファとして適しているとしています。

```cpp
class mutable_buffer {
  unsigned char* p_ = nullptr;
  std::size_t n_ = 0;
public:
  mutable_buffer() = default;
  mutable_buffer(mutable_buffer const&) = default;
  mutable_buffer& operator=(mutable_buffer const&) = default;
  constexpr mutable_buffer(void* data, std::size_t size) noexcept
      : p_(static_cast<unsigned char*>(data)), n_(size) { }
  constexpr void* data() const noexcept { return p_; }
  constexpr std::size_t size() const noexcept { return n_; }
  constexpr mutable_buffer& operator+=(std::size_t n) noexcept
      { p_ += n; n_ -= n; return *this; }
};

class const_buffer {
  unsigned char const* p_ = nullptr;
  std::size_t n_ = 0;
public:
  const_buffer() = default;
  const_buffer(const_buffer const&) = default;
  const_buffer& operator=(const_buffer const& other) = default;
  constexpr const_buffer(void const* data, std::size_t size) noexcept
      : p_(static_cast<unsigned char const*>(data)), n_(size) { }
  constexpr const_buffer(mutable_buffer const& b) noexcept
      : p_(static_cast<unsigned char const*>(b.data())), n_(b.size()) { }
  constexpr void const* data() const noexcept { return p_; }
  constexpr std::size_t size() const noexcept { return n_; }
};
```

これはNetoworking TSにすでにあるものです。

これらは`span<byte>`に対応するバッファ型であり、バッファ配列型ではありません。バッファ配列型はこれらの`range`（`vector<mutable_buffer>`など）で表現するようにしています。`mutable_buffer`が要素単位の操作をサポートしていることと、バッファ型が`span<byte>`ではないことでI/Oバッファ配列専用のアルゴリズムを提供可能になり、前述の問題が解消されるためです。
